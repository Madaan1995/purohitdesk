### `app.bookings` (tenant)

| Column | Type / rule |
| --- | --- |

| `booking_number` | text `PD-YY-NNNN`; YY = year of creation **in the organization's time zone** (AUTO-DECIDED), NNNN = `seq_no` zero-padded to 4, longer after 9999 (`PD-27-10000`); `UNIQUE (org_id, booking_number)` |

| `offering_id` | uuid **NOT NULL** (AUTO-DECIDED); FK `(offering_id, org_id) → offerings` |
| `title` | text NULL, 1–120 (free text, erasable) |
| `location` | text NULL, 1–500 ("place"; free text, erasable) |
| `notes` | text NULL, 1–2000 (free text, erasable) |
| `agreed_dakshina_paise` | bigint NULL, 0–10^11 (the agreed amount the M9 ledger compares against). The form pre-fills the offering's suggested dakshina; the database copies nothing. |

| `timezone` | IANA zone (`tg_validate_timezone`), default = the organization's at creation |

| `is_time_tentative` | boolean, default false; only with times |

| `buffer_overlap_ack` | boolean, default false (written from M7) |
| `source` | `PRIEST_DIRECT` (P0 only), immutable |
| `created_via` | `MANUAL` (AUTO-DECIDED: `VOICE` is added with M14), immutable |
| `cancel_reason` | text NULL, 3–500; only on CANCELLED (free text, erasable) |
| `created_by` | uuid → app_users, immutable |
| `confirmed_at`, `completed_at`, `cancelled_at` | timestamptz; CHECK that they match the status (DRAFT: none; CONFIRMED: confirmed; COMPLETED: confirmed + completed; CANCELLED: cancelled, never completed) |
| `version`, `created_at`, `updated_at` | `tg_bump_version` |

Indexes (spec §04 §6): `(org_id, starts_at)`, `(org_id, customer_id, created_at DESC)`, `(org_id, status, local_date)`,
plus `(org_id, local_date, seq_no)` for the list.

**Guard `tg_booking_guard`** (BEFORE UPDATE): transitions DRAFT→DRAFT/CONFIRMED/CANCELLED, CONFIRMED→CONFIRMED/
COMPLETED/CANCELLED; anything else PD410 `INVALID_TRANSITION {from, to}`. `id`, `org_id`, `seq_no`,
`booking_number`, `source`, `created_via`, `created_by`, `created_at` → PD422 `IMMUTABLE_FIELD`. On COMPLETED/
CANCELLED only `notes` may change, and `title`/`location`/`cancel_reason` may only be cleared to NULL (erasure, M12);
anything else PD410. No DELETE for anyone.

### `app.booking_assignments` (tenant)

`id`, `org_id`, `booking_id`, `organization_priest_id`, `role` (`LEAD`/`ASSISTANT`), `position` 1–11, `created_at`.
FKs `(booking_id, org_id) → bookings`, `(organization_priest_id, org_id) → organization_priests`; UNIQUE
`(booking_id, organization_priest_id)`, `(booking_id, position)`; partial UNIQUE `(booking_id) WHERE role = 'LEAD'`.
`priest_ids` order = position; first = LEAD (spec §05 §5). Replaced as a whole when a draft's priests change.

### `app.calendar_reservations` (tenant; cross-org reads only through `app_freebusy`)

`id`, `org_id`, `kind` (`BOOKING`/`BLOCK`), `booking_id` (required iff BOOKING), `organization_priest_id`,
`priest_profile_id`, `span` tstzrange `[)`, `buffer_span` tstzrange (`buffer_span @> span`), `status`
(`ACTIVE`/`RELEASED`), `note` (only on BLOCK rows, ≤ 500; blocks arrive in M8), `created_by`, `created_at`,
`released_at`, `released_by`.
- `calendar_reservations_no_overlap`: `EXCLUDE USING gist (priest_profile_id WITH =, span WITH &&) WHERE (status =
  'ACTIVE')` — keyed on the **global** profile, so it holds across practices.
- `calendar_reservations_one_active_per_assignment`: partial UNIQUE `(booking_id, organization_priest_id) WHERE status
  = 'ACTIVE'`.
- FKs `(org_id, organization_priest_id, priest_profile_id) → organization_priests (org_id, id, priest_profile_id)`
  (proves the profile matches the link), `(booking_id, org_id) → bookings`.
- GiST `(priest_profile_id, buffer_span) WHERE ACTIVE`, `(org_id, booking_id)`.
- Guard `tg_reservation_guard`: the only UPDATE is `status` ACTIVE→RELEASED with `released_at`/`released_by`; DELETE
  and TRUNCATE → PD405 `APPEND_ONLY`.

### `app.booking_events` (tenant, append-only)

`id` bigint identity, `org_id`, `booking_id`, `event`, `actor_user_id`, `data` jsonb object, `created_at`. FK
`(booking_id, org_id)`. UPDATE/DELETE/TRUNCATE → PD405. Index `(org_id, booking_id, created_at)`.

### Deferred invariant triggers (`tg_booking_invariants`, PD500 at COMMIT)

Constraint triggers `DEFERRABLE INITIALLY DEFERRED` on `bookings`, `booking_assignments` and
`calendar_reservations` re-check each touched booking at COMMIT:
- CONFIRMED/COMPLETED ⇒ exactly one LEAD, ≤ 11 assignments, and for every assigned priest exactly one ACTIVE BOOKING
  reservation whose `span` = `[starts_at, ends_at)` and `buffer_span` = the buffered span; no ACTIVE reservation of a
  priest who is not assigned.
- DRAFT/CANCELLED ⇒ no ACTIVE reservation.

## 3. Functions (owner `app_domain` unless noted; recipe: permission → idempotency → lock → version → validate → write → event → finish)

| Function | Permission | Behaviour |
| --- | --- | --- |
| `create_booking(p_fields jsonb, p_confirm boolean, p_idem_key, p_request_hash)` | BOOKING_CREATE; with `p_confirm` also BOOKING_CONFIRM, or BOOKING_CONFIRM_OWN when the actor is the LEAD | Fields: `customer_id`, `offering_id` (required), `title`, `location`, `notes`, `agreed_dakshina_paise`, `timezone` (default org), `local_date`, `starts_at`, `ends_at`, `is_time_tentative`, `buffer_before_min`, `buffer_after_min`, `priest_ids` (organization_priest ids, ≤ 11, distinct, of this practice). `local_date` may be omitted when `starts_at` is given (computed); when given it must match. Unknown fields → PD422. Number from `org_sequences`. Event CREATED (+ CONFIRMED). |
| `update_booking(p_booking_id, p_expected_version, p_patch jsonb, p_idem_key, p_request_hash)` | BOOKING_EDIT; changing `priest_ids` as a PRIEST (BOOKING_CONFIRM_OWN without BOOKING_CONFIRM) requires being LEAD before **and** after | JSON patch (null clears; absent keeps). DRAFT: every field. CONFIRMED: schedule fields (`timezone`, `local_date`, `starts_at`, `ends_at`, `is_time_tentative`, `buffer_*`, `priest_ids`) → PD422 reason `USE_RESCHEDULE`; the rest may change. COMPLETED/CANCELLED: only `notes`, else PD410. Event EDITED with the changed field names. |
| `confirm_booking(p_booking_id, p_expected_version, p_priest_ids uuid[], p_idem_key, p_request_hash)` | BOOKING_CONFIRM, or BOOKING_CONFIRM_OWN as LEAD before and after any `priest_ids` change | DRAFT only (else PD410). Needs a time (PD422 `TIME_REQUIRED`, `details.field = starts_at`) and a LEAD (PD422 `LEAD_REQUIRED`, `details.field = priest_ids`). NULL buffers take the LEAD's defaults. `_reserve_booking`. |
| `cancel_booking(p_booking_id, p_expected_version, p_reason text, p_idem_key, p_request_hash)` | BOOKING_CANCEL, or BOOKING_CANCEL_OWN as LEAD | DRAFT (reason optional) or CONFIRMED (reason 3–500 chars required, PD422 `field = reason`); releases every ACTIVE reservation; else PD410. |
| `complete_booking(p_booking_id, p_expected_version, p_idem_key, p_request_hash)` | BOOKING_COMPLETE, or BOOKING_COMPLETE_OWN as LEAD | CONFIRMED only (else PD410); `now() < starts_at` → PD422 `NOT_STARTED`, `field = starts_at`. Reservations stay ACTIVE as history. |
| `get_booking(p_booking_id)` | BOOKING_READ (every role; SECURITY INVOKER, RLS decides) | The read model below, or NULL (→ 404). |
| `_reserve_booking(p_booking_id)` | internal | Spec §05 §3: per-priest `pg_advisory_xact_lock` in `priest_profile_id` order; `_priest_conflicts` for each; any CEREMONY overlap → `23P01 BOOKING_CONFLICT` with `details.conflicts = [{starts_at, ends_at, same_org, booking_id (same org only)}]`; then one ACTIVE reservation per priest (the exclusion constraint is the final arbiter). **M6 does not check travel buffers** (`buffer_span` is stored; buffer-only overlaps are allowed until M7). |
| `_priest_conflicts(p_priest_profile_id, p_span, p_buffer_span, p_exclude_booking)` | owner **`app_freebusy`**, SECURITY DEFINER, executable by `app_domain` only | Verifies the profile is linked to the current tenant (else PD404 `priest`); returns ACTIVE reservations of that human in **every** organization overlapping `p_buffer_span` or whose buffer overlaps `p_span`, as `(kind CEREMONY/BUFFER, starts_at, ends_at, same_org, booking_id)`, with `booking_id` NULL for other organizations. VOLATILE, so it reads what committed while waiting on the advisory lock. |
| `_lock_booking`, `_assert_any`, `_assert_booking_permission`, `_set_assignments`, `_booking_out`, `_event`, `_check_booking` | internal (invoker) | Helpers. `_assert_any` runs before validation (spec defect #4), so an unauthorised caller never learns the rules. |

**Booking read model (`_booking_out`, AUTO-DECIDED shape)**: `{id, booking_number, status, customer: {id,

Not-found answers: another practice's booking, customer, offering or priest link → PD404 (never 403). Past times are

## 4. API (shapes AUTO-DECIDED — needs founder review)

| Route | Permission | Notes |
| --- | --- | --- |
| `GET /bookings` | BOOKING_READ | `?status=&customer_id=&from=&to=` (local dates; `to − from` ≤ 366 days), `limit` ≤ 100, keyset `cursor` on `(local_date, seq_no)`; `{data: BookingSummary[], next_cursor}` |

| `POST /bookings/{id}/confirm` | BOOKING_CONFIRM[_OWN] | If-Match; `{priest_ids?}` |
| `POST /bookings/{id}/cancel` | BOOKING_CANCEL[_OWN] | If-Match; `{reason?}` |
| `POST /bookings/{id}/complete` | BOOKING_COMPLETE[_OWN] | If-Match; `{}` |

All writes need `Idempotency-Key`. Times are RFC 3339 instants; the form converts the local date and time in the
practice's time zone with `src/domain/time.ts` (never the server clock for "today": the org time zone).
`BookingSummary` = `{id, booking_number, status, customer: {id, display_name}, offering: {id, name_hi, name_en},
title, local_date, starts_at, ends_at, timezone, is_time_tentative, version}`.

## 6. UI

- Header navigation gains **Bookings** (बुकिंग).
- `/bookings`: upcoming bookings from today (org time zone), grouped by date; "time not fixed" shown for date-only
  drafts; filter "past"; "New booking".
- `/bookings/new` (also from a customer's page with the customer pre-selected): customer search, offering (fills the
  duration and the suggested dakshina), date (required), start time (optional) + duration, "time is approximate
  (window)" toggle, place, title, notes, dakshina ₹, priest (hidden when the practice has one priest). Buttons:
  "Save draft" and "Save and confirm".
- `/bookings/{id}`: number, status, date and time in the practice's time zone (≈ for tentative), customer, ceremony,
  place, priests, dakshina; actions by permission: Edit, Confirm, Cancel (asks for a reason when confirmed; confirm
  dialog), Complete (confirm dialog). A conflict shows "इस समय पंडित जी की दूसरी पूजा है" and the busy time(s),
  never another practice's details; "a time is needed" for a date-only draft.
- `/bookings/{id}/edit`: the same form (PATCH with If-Match); schedule fields are read-only once confirmed (they move
  with reschedule in M7).

## 7. Tests (AUTO-DECIDED — needs founder review)
